# Alur Pengepul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pengepul menerima laporan baru sebagai notifikasi HP, mengambilnya lewat link pribadi tanpa login, chat WA ke pemilik, dan menutupnya dengan kode serah terima. Warga mendapat kabar lewat email dan dashboard.

**Architecture:** Logika domain murni di `lib/collector/` (tanpa Supabase, diuji dengan store di memori). Akses data lewat satu interface `CollectorStore`, dengan implementasi Supabase memakai kunci secret di server. Notifikasi lewat interface `Notifier` (web push + SMTP, fallback console). Halaman pengepul `/p` dan `/j/[token]` memakai server action. Halaman admin dan aksi warga memakai route API ber-Bearer token seperti `/api/reports`.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, Supabase (`@supabase/supabase-js`), `web-push`, `nodemailer`, Leaflet (sudah ada), tes `node --test` dengan `--experimental-strip-types`.

**Spec:** `docs/superpowers/specs/2026-11-24-pengepul-whatsapp-design.md`

## Global Constraints

- Baca panduan Next.js yang relevan di `node_modules/next/dist/docs/` sebelum menulis route, page, server action, manifest, atau `headers()`. Versi ini berbeda dari data latih (contoh: `params` di page/route adalah `Promise`).
- `pnpm` saja. Dependensi baru: `web-push`, `nodemailer`, `@types/web-push`, `@types/nodemailer`. Tidak ada yang lain.
- Tambahkan `"allowImportingTsExtensions": true` ke `tsconfig.json`. Semua file di `lib/collector/` dan `lib/notifications/` memakai impor relatif ber-ekstensi `.ts` dan **tidak** mengimpor `@/...` atau `server-only`, supaya tes bisa mengimpornya langsung.
- Satu interface/type per file di folder `interfaces/` milik fiturnya. Tidak ada definisi type di file UI.
- Server action di folder `actions/` per fitur dengan `"use server"`. Tidak ada logika bisnis di komponen.
- UI mengikuti `AGENTS.md`: palet token, tanpa emoji/unicode non-ASCII, Flexbox, target sentuh 44px, satu aksi utama per layar, error di bawah kolomnya, setiap `page.tsx` mengekspor `metadata` (`title` + `description`). Halaman `/p`, `/j/*`, `/admin/*` memakai `robots: { index: false, follow: false }`.
- Angka dari spec, di `lib/collector/rules.ts`: `WAVE_SIZE = 3`, `WAVE_INTERVAL_MINUTES = 30`, `MAX_WAVES = 3`, `RADIUS_MIN_KM = 1`, `RADIUS_MAX_KM = 30`, `HANDOVER_MAX_ATTEMPTS = 5`, `HANDOVER_LOCK_MINUTES = 15`, `NOTIFY_MAX_ATTEMPTS = 3`, `DIGEST_HOURS_WIB = [8, 16]`, `PRICE_MAX_IDR = 100_000_000`.
- Teks UI dan notifikasi dalam Bahasa Indonesia.
- Setiap task diakhiri `pnpm test`, `pnpm lint`, dan `pnpm exec tsc --noEmit` yang bersih.

## Review Focus

1. **Dua pengepul menekan "Ambil" bersamaan:** hanya satu menang, yang lain melihat "sudah diambil". Tes di Task 4 (`claim race`), dan implementasi Supabase di Task 3 wajib memakai update bersyarat yang mengembalikan baris.
2. **Link lama dibuka setelah laporan dibatalkan, selesai, atau dilepas lalu diambil orang lain:** pengepul lama melihat keadaan tertutup dan tidak pernah melihat alamat atau nomor. Tes di Task 4 (`stale offer`).
3. **Format nomor HP warga yang beragam** (`0812 3456 7890`, `+62-812-3456-7890`, `812345678901`, `62812...`, huruf, terlalu pendek): dinormalisasi atau ditolak dengan pesan di bawah kolom. Tes di Task 1.
4. **Notifikasi gagal atau kredensial kosong:** laporan warga tetap tersimpan dan respons tetap sukses, kegagalan masuk `notification_log`. Tes di Task 5 dan Task 6.
5. **Cron terpanggil dua kali atau terlambat:** tidak ada offer ganda untuk pengepul yang sama, dan gelombang tidak melompat. Tes di Task 6 (`tick twice`).

**Interfaces:**
- Consumes: Task 1 (`decideWave`, `areaCovers`), Task 4 (`notifyAdmin`, `notifyCollector`), Task 5 (`dispatchWave`).
- Produces:
  - `runDispatchTick(store, notifier, now, appUrl): Promise<{ waves: number; escalated: number }>`. Untuk setiap laporan pending: `"wave"` memanggil `dispatchWave`, `"escalate"` mengirim `adminAlertEmail("unclaimed")` **sekali** (tandai dengan `wave_count = MAX_WAVES + 1`).
  - `runDigest(store, notifier, now, appUrl): Promise<{ sent: number }>`. Untuk setiap pengepul `digest` yang aktif dan tidak dijeda, hitung laporan pending di areanya dengan `createdAt > lastDigestAt`. Jika N > 0, kirim `digestPush` lalu set `last_digest_at = now`.
  - `retryNotifications(store, notifier, now): Promise<{ retried: number }>` untuk entri `failed` dengan `attempts < NOTIFY_MAX_ATTEMPTS`.
  - `verifyCronSecret(request: Request, secret: string | undefined): boolean` memakai `crypto.timingSafeEqual`. Secret kosong menghasilkan `false`.
  - Route `POST` mengembalikan 401 tanpa secret yang benar, lalu menjalankan tick + retry (dispatch) atau digest dan mengembalikan ringkasan JSON. `GET` mengembalikan 405.
